How to use this calculator

Same model as the Excel workbook. Configure your topology once, paste measured GB, then read the chargeback. Yellow cells are the ones you edit.

Yellow = editable

Every yellow field or table cell can be changed. White / calculated values update automatically. Your edits stay in this browser until you reset or clear site data.

What each block means

Open Parameters first. The four ideas below are the whole model.

1 · Global contract

  • Deployment — Elastic Cloud or on-premises (labels and default unit adapt).
  • Cost unit — ECU, EUR, USD… used in all totals.
  • Hours / month — usually 730; multiplies hourly rates.
  • Annual commit / budget — Cloud commit or on-prem license/budget target.
  • Margin — uplift on that target (e.g. 0.03 = +3%).
  • Other annual — extras (egress, snapshot API, ops) folded into coverage math.

2 · Storage tiers

  • Enabled — tick only tiers that exist (hot-only, or +warm/cold, or +frozen).
  • Effect — Measurement GB columns and environment rate columns follow this list.
  • Snapshot allocation — which tier’s GB share pays the snapshot/backup bill (Auto = frozen→cold→warm→hot).
  • Unused tiers — leave disabled; rates and GB stay at 0 and do not affect the bill.

3 · Environments (clusters)

  • Code — short id used in Measurement (DEV, INT, PROD, MON…). Sample PRE/PRO/MON are examples only.
  • Tier rates — cost per hour for each enabled tier in that cluster.
  • Kibana / Integrations / Tiebreaker — Cloud platform components; set to 0 on-prem if not applicable.
  • Snapshots / month — closed-month snapshot (or backup) cost for that env.
  • Surcharge ✓ — families in this env share the commit/budget uplift. Untick for dedicated clusters (e.g. monitoring).

4 · Measurement

  • One row = one family — index pattern or data stream you want to charge back.
  • Env — must match an Environments code (drives which rates apply).
  • GB per tier — measured size; this is what drives the share (not events/s or KB/doc).
  • CSV — import/export to replace the fictional sample with your inventory.

Recommended flow

1
Set deployment & global figures

In Parameters: Cloud or on-prem, cost unit, hours/month, annual commit or budget, margin and other annual cost.

2
Enable the tiers you actually use

Hot-only? Enable Hot only. ILM with warm/cold? Enable those. Searchable snapshots? Enable Frozen. Then choose how snapshots are allocated.

3
Define environments & rates

Add or rename cluster codes, fill yellow rate cells for enabled tiers, platform columns if Cloud, snapshots/month, and tick Surcharge where commit uplift applies.

4
Fill Measurement

One yellow row per family: name, env, GB in each enabled tier. Events/s and KB/doc are optional context only.

5
Read Allocations

Without admin cost = pure capacity + snapshots. With admin cost = same plus surcharge on marked environments.

6
Workloads & Any family

Group families for a business owner, or open Any family to walk the calculation step by step for audits.

Tips

  • Edits are saved in the browser (localStorage). Export CSV before clearing cache.
  • Events/s and KB/doc never enter the cost formula — only GB share × rates × hours (+ snapshots + optional surcharge).
  • Sample names and volumes are fictional. Do not paste real customer inventories into a public fork.
  • On-prem: set platform rates to 0 if unused, switch unit to EUR/USD, and treat “commit” as your annual budget or license target.
  • Need a clean start? Measurement → Reset sample (also restores default tiers and environments).
